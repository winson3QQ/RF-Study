SDR 情境化課程 📻

無線電參數實戰學習：從真實災害情境開始。先遇到困難，再學會解決——理解才會深入。

課程介紹：情境化學習法

為什麼要用「情境」學習無線電參數？

傳統教學告訴你「CTCSS 是 67-250Hz 的亞音頻」，但你還是不懂為什麼要學。

情境化學習先呈現真實困難：「地震後 5 支隊伍搶 1 個頻率，怎麼區分？」

這時候你才明白：「啊，CTCSS 能解決這個問題！」

從「為什麼需要」到「如何使用」，理解才會深入。

📚 課程結構：七大真實情境
  1. 情境1：地震後，手機基站倒塌，5 支隊伍只有 1 個頻率
    → 學習：頻率 + CTCSS（多隊共用一頻）
  2. 情境2：山區救援，信號微弱，隊員聽不清
    → 學習：RF 增益 + 靈敏度（信號弱的解決）
  3. 情境3：中繼台故障，隊伍改用直聯，信號更弱
    → 學習：頻寬（12.5kHz vs 25kHz）
  4. 情境4：同一棟建築有 40 個人，只有 1 台對講機
    → 學習：多頻道 + CTCSS 層級（大型指揮）
  5. 情境5：天線被砸壞，信號完全消失
    → 學習：天線設定 + 故障診斷
  6. 情境6：干擾信號，指揮官聽到別人講話
    → 學習：掃頻 + 干擾診斷
  7. 情境7：多支隊伍跨區通訊，直聯無法到達
    → 學習：中繼台 + 頻率對設定

🏘️ 情境1：地震後，手機基站倒塌，5 支隊伍只有 1 個頻率

時間 地震發生後 15 分鐘 地點 通訊指揮所 學習重點 CTCSS + 頻率共享
📍 現場情況
  • 地震規模 6.5，多個基站受損
  • 台北市民防隊（文山、信義、大安、中山、松山五支小隊）
  • 所有手機網路斷掉
  • 僅有對講機可用，但只申請到 1 個頻率：145.500MHz
  • 5 支隊伍都在搶同一個頻率講話，互相干擾，無法協調
⚠ 現場困境指揮官：「北投文山隊回報！」 文山隊：「收到！」 同時，其他隊伍也在發話 → 一團亂，分不出誰是誰。
🎓 解決方案：CTCSS

指揮官的說明：

「我現在給每支隊伍設定一個『私密頻道』，同一個 145.500MHz，但用不同的『鑰匙』」

同一頻率上的 5 支隊伍 145.500 MHz ├─ 隊伍A: CTCSS 67Hz ├─ 隊伍B: CTCSS 88.5Hz ├─ 隊伍C: CTCSS 110Hz ├─ 隊伍D: CTCSS 151.4Hz └─ 隊伍E: CTCSS 180Hz (用 RTL-SDR 可以看到所有 頻率上的亞音峰值) 現場效果： 隊伍A發話 → 只有設 CTCSS=67Hz 的隊伍會聽到 隊伍B發話 → 只有設 CTCSS=88.5Hz 的隊伍會聽到 → 五支隊伍秩序井然，互不干擾
🔬 SDR 實驗：看見 CTCSS
🎯 實驗活動 — 演示步驟
演示流程： 1. 對講機A設 CTCSS=67Hz，發話 GQRX 中 FFT 看到 67Hz 峰值 ✓ 2. 對講機B設 CTCSS=88.5Hz，同時發話 GQRX 中 FFT 看到兩個峰值 (67Hz + 88.5Hz) 3. 解除 CTCSS，所有隊伍互相干擾 GQRX 中只看到一個亂糟糟的 FFT 4. 重新加上正確 CTCSS GQRX 立刻清晰 → 學員： 「啊！我看懂了！」
GQRX FFT 視覺化對比 有 CTCSS 隔離： ┌─────────────────────────┐ │ FFT頻譜（0-300Hz範圍） │ │ │ │ ⚫ ← 67Hz尖峰 │ ╱ ╲ （CTCSS特徵） │ ──────────── │ │ 0 67 200 Hz │ │ │ │ CTCSS=67Hz的隊伍收到訊號│ └─────────────────────────┘ 無 CTCSS 隔離： ┌─────────────────────────┐ │ FFT頻譜 │ │ ▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀ │ │ 全都是雜訊，無法區分 │ │ → 通訊癱瘓 │ └─────────────────────────┘
💡 核心知識點
CTCSS 的作用

在同一頻率上為不同隊伍開啟「靜噪」，實現多隊隔離

技術原理

67-250Hz 的低頻亞音附著在語音上，不同隊伍有不同的「鑰匙」

何時使用

緊急狀況下頻率有限，需要多支隊伍共用一個頻率

限制條件

標準 CTCSS 只有 38 組，最多能隔離 38 支隊伍

✓ 記憶方法CTCSS 不提供保密（仍可聽到發射），只控制「接收喇叭開/關」。
📝 課堂活動：CTCSS 探險隊
🎯 目標 — 認識 38 個 CTCSS 組號

準備材料：對講機設 CTCSS 為不同值輪流發話；GQRX 監聽並記錄瀑布圖；GNU Radio 進行頻域分析。

互動遊戲「尋找隱藏的亞音寶藏」：

  1. 組長發話（CTCSS=88.5Hz）→ 全體用 GQRX 尋找 FFT 中 88.5Hz 峰值 → 誰先發現誰獲勝
  2. 設置接收 CTCSS → 設為正確組號 88.5Hz → 聽到聲音 ✓；設為錯誤組號 123.0Hz → 靜噪關閉 ✗ → 理解「鑰匙」的概念
  3. 多隊伍模擬 → 隊伍A：145.500 + CTCSS 88.5Hz；隊伍B：145.500 + CTCSS 151.4Hz → 同頻不同碼 = 各聽各的
🎯 學習成果檢驗

課程結束時，學員應該能：

  • ✓ 為什麼需要 CTCSS：解決同頻多隊問題
  • ✓ 什麼時候用：緊急狀況下頻率有限
  • ✓ 如何用：每支隊伍一個不同的 CTCSS 碼
  • ✓ 用 SDR 驗證：看 FFT 峰值確認 CTCSS 設定正確
  • ✓ 故障排除：CTCSS 碼不符時的解決方案

🏔️ 情境2：山區救援，信號微弱，隊員聽不清指揮官

時間 地震後 2 小時 地點 山區倒塌建築搜救 學習重點 RF 增益 + 靈敏度
📍 現場情況
  • 搜救隊在山上廢墟，距離指揮所 5km
  • 對講機能收到信號，但很微弱
  • 隊員：「指揮所，我聽不清你在說什麼」
  • 指揮官：「我已經按最大音量在講了，還有辦法嗎？」
⚠ 關鍵認知轉變❌ 錯誤想法：發射功率越大越好。 ✓ 正確做法：調整 RF 增益找到最佳接收點。
🎓 解決方案：RF 增益調整

技術人員用 RTL-SDR 診斷：

「原來你們的對講機 RF 增益設太低了！信號其實有來，但沒有被放大」

用 GQRX 實時演示增益效果： 調整前（RF 增益=10dB）： ┌──────────────────────────┐ │ FFT頻譜 │ │ ▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀ │ │ ▲ ← 微弱信號 │ │ ╱ ╲ │ └──────────────────────────┘ FFT 高度 = 信號強度 = 太弱 調整後（RF 增益=35dB）： ┌──────────────────────────┐ │ FFT頻譜 │ │ ▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀ │ │ ▲▲ │ │ ╱██╲ │ ← 清晰的信號 │ ▀╱████╲▀▀ │ └──────────────────────────┘ FFT 高度 = 清晰可聞！ 隊員：「啊！現在能聽清楚了！」
🔬 SDR 實驗：身體感受學習
🎯 實驗做法
  1. 指揮官在 500m 外發話
  2. 學員A：RF 增益設 10dB → 聽不清
  3. 學員B：RF 增益設 35dB → 清晰！
  4. 學員C：RF 增益設 49dB（最高）→ 聽得到，但噪聲很大，反而更難聽清
💡 重要結論「最大增益 ≠ 最好效果」；「最佳增益 = 信號清晰但沒有過度噪聲」。
📊 RF 增益與靈敏度的關係
增益設定與效果對應表： 增益 FFT山峰 底噪 SNR 語音清晰度 ───────────────────────────────────── 0dB -60dBm -80dB -20 無 10dB -50dBm -75dB -25 無 20dB -40dBm -70dB -30 弱 30dB -30dBm -60dB -30 良好✓ 40dB -20dBm -40dB -20 好但噪聲多 49.6dB -10dBm -20dB +10 噪聲蓋過語音✗ 【最佳增益點】 = 30-35dB（此例）
RF 增益的作用

放大接收機的微弱信號，提升靈敏度

為何不能盲目調高

會把雜訊也放大，降低信噪比

最佳做法

調至「剛好清晰」的位置，信號清晰但沒有過度噪聲

現場應用

信號不好時的第一個調整選項

✓ 記憶方法RF 增益的最佳值依環境而異，沒有「一體通用」的設定。需要根據現場調整。
📝 課堂活動：靈敏度獵人遊戲
🎯 角色分配
  • 隊長（發話者）：在不同距離發話 — 100m、300m、500m、800m、1km
  • 技術員：用 GQRX 監聽，調整 RF 增益，目標讓隊員聽到最清晰的聲音
  • 隊員：聽音質並評分（1 分 = 完全聽不到，5 分 = 很清晰沒雜訊）

每個距離找到「最佳 RF 增益」並記錄表格。結論：距離越遠 → 需要越高的 RF 增益。

🎯 學習成果檢驗

課程結束時，學員應該能：

  • ✓ RF 增益的作用：放大微弱信號
  • ✓ 為什麼不能盲目調高：會把雜訊也放大
  • ✓ 最佳做法：調至「剛好清晰」的位置
  • ✓ 現場應用：信號不好時的第一個調整選項
  • ✓ 用 GQRX 判斷：觀察 FFT 山峰高度和底噪水平

📡 情境3：中繼台故障，隊伍改用直聯，信號卻更弱

時間 救援第 4 小時 地點 不同災區 學習重點 頻寬（12.5kHz vs 25kHz）
📍 現場情況
  • 原本靠中繼台（在信義高樓）轉發信號
  • 中繼台停電受損
  • 隊伍改用直聯（互相直接通話，不經過中繼台）
  • 隊長A和隊長B都在不同的災區，相距 3km
  • 直聯時訊號很弱，幾乎無法通話
⚠ 關鍵認知轉變頻寬不是「美學」選擇，是「效率」選擇。
🎓 解決方案：改用窄頻

技術人員用 GQRX 檢查對講機設定，發現問題：

隊伍A的對講機設定：25kHz（寬頻）；隊伍B的對講機設定：12.5kHz（窄頻）

解釋原理： 25kHz 頻寬 = 信號分散在更寬的範圍 這在有中繼台時沒問題（中繼台功率大） 但直聯時，信號本來就弱 再分散到 25kHz 範圍，能量密度就更低了 12.5kHz 頻寬 = 信號集中在更窄的範圍 在直聯環境中，能量密度高 因此距離更遠、清晰度更好
用 GQRX FFT 對比： 25kHz 模式（能量分散）： ┌─────────────────────────┐ │ ▲ │ │ ╱ ╲ │ │ ╱ ╲ 寬度大 │ │ ────────────────── │ │ 145.4 145.5 145.6 │ │ 能量密度低 → 易互相干擾 │ └─────────────────────────┘ 12.5kHz 模式（能量集中）： ┌─────────────────────────┐ │ ▲ │ │ ╱ ╲ │ │ ╱ ╲ 寬度小 │ │ ────────────────── │ │ 145.4 145.5 145.6 │ │ 能量密度高 → 清晰度優 │ └─────────────────────────┘
🔬 SDR 實驗：頻寬實驗室
🎯 對比測試

設定1：145.500MHz，25kHz，1W 功率，無 CTCSS

設定2：145.500MHz，12.5kHz，1W 功率，無 CTCSS

測試環境25kHz 成功率12.5kHz 成功率性能差異
室內 300m 遠70%95%窄頻 +25%

✓ 記憶方法相同功率下，窄頻在困難環境中優勢明顯。這就是為什麼現代民防都要用 12.5kHz。
頻寬的影響

不是「美學」選擇，是「效率」選擇

何時用寬頻

有中繼台幫助轉發時可用

何時用窄頻

直聯、信號弱、需要節省電力時

現場決策

災害時應優先用窄頻提高效率

🏢 情境4：同一棟受困建築有 40 個人，只有 1 台對講機

時間 地震後 6 小時 地點 倒塌辦公大樓 學習重點 多頻道 + CTCSS 層級管理
📍 現場情況
  • 辦公大樓倒塌，40 人被困不同樓層
  • 搜救隊只有 1 台對講機與指揮所通訊
  • 需要逐層確認傷患數量、位置、傷情
  • 不能讓 40 人都搶對講機講話
⚠ 傳統做法（很低效）「大樓，報告傷患！」→ 40 個人同時尖叫 → 對講機收到雜訊 → 指揮所什麼都聽不清。
🎓 解決方案：層級化指揮通訊
建立「指揮系統」 主頻率：145.500MHz └─ 用 CTCSS 分層管理 ├─ CTCSS 67.0Hz：1樓、2樓隊 ├─ CTCSS 88.5Hz：3樓、4樓隊 ├─ CTCSS 110.9Hz：5樓、6樓隊 └─ CTCSS 131.8Hz：指揮所 報告流程： 1. 1樓隊員報告傷患：「1樓東側發現5人」 （按住 PTT + CTCSS 67Hz 自動發射） 2. 指揮所只設定無 CTCSS（所有頻道都能收） 「收到，1樓東側5人」 3. 3樓隊員看到1樓的報告，知道自己輪到了 報告：「3樓南側發現8人，其中2人受傷」 4. 指揮官在指揮所統一記錄 → 有組織、不混亂
🔬 SDR 監控全景
用 GQRX 監控中繼台運作 設定 RTL-SDR + GQRX 進行「通訊監測」 監聽 145.500MHz，看到： ┌─────────────────────────┐ │ 145.500MHz FFT圖 │ │ │ │ 67Hz ✓ 1樓報告中 │ │ 88Hz │ │ 110Hz │ │ 131Hz │ │ │ │ 瀑布圖：不同高度 │ │ 代表不同樓層在通話 │ │ → 指揮官清楚掌握 │ └─────────────────────────┘
頻率是共享的「馬路」

145.500MHz 是通訊的基本管道

CTCSS 是號碼牌

每支隊伍的「身分」，識別來源

層級管理

越高位置越包容（無 CTCSS 設定）

應急策略

限制資源時如何最有效地協調

✓ 記憶方法有組織的通訊系統，救援效率能提升 10 倍。
📝 課堂活動：救災通訊指揮模擬
🎯 場景 — 模擬大樓被困 40 人，5 支隊伍搜救

器材：5 台對講機（分別設不同 CTCSS）；1 台指揮機（無 CTCSS 限制）；GQRX 監聽軟體顯示在大螢幕。

流程：

  1. 學員分組（每組 1 支隊伍 + 幾個「傷患」）
  2. 輪流報告傷患情況
  3. 指揮官（教官）記錄所有報告
  4. 檢查是否有遺漏或混亂

課程結束時，學員應該能：

  • ✓ 分配 CTCSS 碼給不同隊伍

  • ✓ 快速找出通訊故障點
  • ✓ 在大規模救援中協調多支隊伍

🔧 情境5：天線被砸壞，信號完全消失

時間 救援第 8 小時 地點 災區指揮所 學習重點 天線診斷 + 故障排除
📍 現場情況

突然通訊中斷：

  • 指揮官：「所有隊伍，回報！」
  • 無回應…無回應…
  • 5 分鐘後：「對講機還有電，但收不到任何聲音」
⚠ 危機時刻通訊完全中斷意味著救援協調無法進行，需要快速診斷和解決問題。
🎓 SDR 診斷流程
🎯 步驟1：檢查頻率設定用 GQRX 監聽 145.500MHz。結果：完全無信號（FFT 全是底噪）。
🎯 步驟2：檢查天線肉眼檢查發現天線被坍塌物砸歪。拆下天線，接上 RTL-SDR + 跳線監聽相同頻率。結果：仍無信號 → 天線損壞確診。
🎯 步驟3：用備用對講機測試備用對講機發話到 145.500MHz，用 RTL-SDR 監聽 → 看得到清晰信號！結論：原對講機的發射端可能也損壞。
🎯 步驟4：解決方案臨時方案：用備用對講機繼續通訊；長期方案：找一根臨時天線（甚至可以用電話線臨時綁起來當 λ/4 天線）；驗證：接上臨時天線後再測，用 RTL-SDR 確認信號恢復正常。
沒有 SDR vs 有 SDR 的診斷時間 沒有 RTL-SDR 的做法： 「對講機沒聲音」 → 猜測是頻率不對？CTCSS不對？電池沒電？ → 逐一試錯，浪費時間 → 診斷時間：30 分鐘以上 有 RTL-SDR 的做法： 「立刻看 FFT 圖」 → 無信號 = 肯定是硬體問題（天線或電台） → 換天線立即驗證 → 診斷時間：2-5 分鐘
✓ 記憶方法在緊急情況下，快速診斷的能力能救人。SDR 成為現場應急的「診斷工具」。

🌉 情境7：多支隊伍需要跨區通訊，直聯無法到達

時間 救援第 24 小時 地點 不同行政區 學習重點 中繼台 + 頻率對設定
📍 現場情況
  • 文山區搜救隊需要與信義區協調
  • 兩地直線距離 3km，但有山丘遮擋
  • 頻率：145.500MHz
  • 直聯完全無法通話
⚠ 問題分析地形遮擋 = 信號無法直線傳播，需要用中繼台來「轉發」信號。
🎓 解決方案：架設臨時中繼站
中繼台原理（信號轉發）： 直聯失敗的情況： 隊伍A ←(無法直聯)→ 隊伍B 無法翻過山丘 使用中繼台解決： 隊伍A 發 145.500 ↓ 中繼台(放在高處) 收 145.500 → 發 145.620 ↓ 隊伍B 收 145.620 頻率設定： 隊伍A/B 都設： 發射頻率：145.500 接收頻率：145.620 中繼台設： 接收：145.500 發射：145.620
🔬 SDR 監控中繼台運作
🎯 設定 RTL-SDR + GQRX 進行「中繼台健康檢查」監聽 145.500 + 145.620 雙頻。
